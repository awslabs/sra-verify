# Requirements Document

**Feature:** Organizations provider

**Spec directory:** `.kiro/specs/organizations-provider/`

**Supersedes:** GitLab MR !54, `refactor/shared-org-accounts-accessor` (986bced on main c55893a), which is not merged as-is. Phase 1 of this feature is the MR that replaces it.

**Evidence:** `.tmp/review/mr54-strategic-review.md` and the artefacts under `.tmp/review/`; the !54 developer's own A/B report, `sratester/org-accounts-refactor-test-report.md`. Line numbers below are the !54 branch unless marked `main`.

## Introduction

AWS Organizations is the one service every other service in this scanner leans on. Fifteen checks need the account list to say which member accounts a control must cover; eight service clients ask who the delegated administrator is; four paths describe the organization to learn the management account; Security Hub reads roots, policies and effective policies to evaluate central configuration. None of that is Organizations' own business, and on `main` none of it is in one place. On the pre-MR tree `organizations:ListAccounts` is issued from six client copies: three paginate and cache per Region, so one scan repeats the same organization-wide sweep once per Region per service; one is never cached; one (Inspector) reads the **first page only**, so SRA-INSPECTOR-07 has never seen the 21st account of any organization; and one is Organizations' own, pinned to `us-east-1`. `ListDelegatedAdministrators` is still copied across **eight** clients on the !54 branch (`.tmp/review/q1-orgops.txt`), `DescribeOrganization` across the `iam` and `config` clients plus a raw boto3 call in `SecurityHubCheck.get_organization()` (`securityhub/base.py:909–980`) plus `ScanContext.get_management_account_id`, and `ListRoots` / `ListPoliciesForTarget` / `DescribePolicy` / `DescribeEffectivePolicy` from `SecurityHubClient` as well as `OrganizationsClient`.

Every copy is its own client binding, its own cache slot, its own choice of Region, and its own classification. The consequences are not hypothetical. The same `AWSOrganizationsNotInUseException` from `ListDelegatedAdministrators` is a FAIL when an IAM check reads it (`iam/base.py:83` declares it) and an ERROR when a Config, CloudTrail, Access Analyzer, Macie, Security Hub, Security Incident Response or Security Lake check reads it (none of them does). The one live regression !54 produced — 176 audit-account rows across SRA-SECURITYLAKE-06 to -13 flipping PASS to FAIL — came from `SecurityLakeCheck._prime_region_log_sources` reading the account list straight out of a cache slot by key string, a slot nothing wrote any more; the fix changed the key it reads, and the primer still reads a slot raw (`securitylake/base.py:477–480`), correct today only because eight other files happen to call the accessor first. And `OrganizationsClient.__init__` pins the literal `us-east-1` (`organizations/client.py:31–32`): correct in the `aws` partition, wrong in every other, and !54 routes all six account-list paths through it, so fourteen checks that were partition-correct by construction on `main` would ERROR in GovCloud on the branch (`.tmp/review/endpoint_probe.txt`: `organizations` is partition-global, not Region-less).

!54 consolidated the six `ListAccounts` copies into `OrganizationAccountsMixin.get_organization_accounts()` under `services/organizations/accounts.py`, mixed into six service base classes. The strategic review found it sound as the code stands — it honours the error-result contract, keeps the raw call inside a `client.py` where `util/generate_iam_policy.py` can see it, and avoids a static `core → services` import — and it recommended merging with follow-ups. The repository owner decided otherwise, and this document does not relitigate that decision: a cross-service accessor inherited by service bases is a second inheritance axis that the property suite cannot see (`test_accessor_cache_property._public_methods` enumerates `vars(base)`, so the mixin needed the hand-maintained `_SHARED_ACCESSORS` list in `test_check_classification_property.py:67`, with no test that the list is complete), and the natural generalisation — an Organizations facade mixin carrying `get_delegated_administrators` and `get_organization` too — grows that axis rather than retiring it. The repository already has the right home for per-scan, cross-service state: `ScanContext` owns it, and `SecurityCheck` reaches it through read-only delegating properties (`self.regions`, `self.account_id`, `self.audit_accounts`). Organization data belongs there, as `self.organization`.

So this feature introduces an **Organizations provider**: one object in `core/`, constructed with the `ScanContext` and exposed as `ctx.organization`, wrapping a relocated, partition-aware `OrganizationsClient` with cached typed accessors under the `organizations` namespace, owning one `NOT_CONFIGURED_ERRORS` table for Organizations operations that `is_not_configured` consults after the check's own service table. It lands in two MRs. **Phase 1** replaces !54: the provider with `accounts()` alone, the relocated client, `ScanContext.organization` and `SecurityCheck.organization`, the fifteen call sites and the Security Lake primer migrated, the mixin and `_SHARED_ACCESSORS` deleted, the IAM generator taught to see calls issued from `core/`, and the harness and steering brought along — and it must be verdict-stable against both `main` and the !54 branch. **Phase 2** brings the rest of the surface behind the same seam, retires `org_client` from every service client, migrates `ScanContext`'s three raising accessors to the same model, and unifies the eight `ListDelegatedAdministrators` classifications with A/B evidence for every row that moves.

Two things from the pre-spec review are carried here as requirements and one is corrected. Carried: the partition pin (S1), the Security Lake primer's raw slot read (S3), and the unchecked `_SHARED_ACCESSORS` list (S4), the last of which the provider makes structurally unnecessary. Corrected: the review predicted a new failure for SRA-INSPECTOR-07 above 100 accounts (S2), because `inspector2:BatchGetAccountStatus` caps `accountIds` at 100 and the paginated read can now exceed it. On both `main` and the branch, `InspectorCheck.batch_get_account_status` already slices its input into batches of 10 (`inspector/base.py:284`; `main:301`) before the client is called, so the cap is not reachable. The docstring's "accepts at most 10 accounts" is wrong — the cap is 100 — but the behaviour is conservative rather than defective. Requirement 8 holds the invariant with the 101-account test the review asked for and leaves the batch size to the design.

The verdict-stability property is the whole point of doing this before merge rather than after. A refactor that moves no `Status` cell can be reviewed by diffing two scans; one that moves some cannot be separated from a regression. Phase 1 therefore admits exactly two kinds of difference — order-only cells built from a `set`, which already vary run to run on `main`, and the Inspector first-page effect against `main` in an organization of more than 20 accounts, which the 13-account test organization cannot exercise — and rejects everything else.

## Glossary

### Domain terms

- **Organizations provider**: The new object in `core/` that owns every read of AWS Organizations data for a scan. Reached from a check as `self.organization`, from the context as `ctx.organization`. Not a `SecurityCheck`, not a service base, not a mixin.
- **Provider accessor**: A cached typed method on the Organizations provider, e.g. `accounts()`. Returns a named-key success dict or an error result unchanged, caches only the former, and takes no Region argument because Organizations answers are organization-wide.
- **Organizations client**: `OrganizationsClient`, relocated from `services/organizations/client.py` to `core/`, inheriting `AWSClient`, with its seven methods and the byte-identical handler unchanged and its Region derived from the scan instead of the literal `us-east-1`.
- **Scan Region**: A Region in the scan's `--regions` list or, absent one, the session's configured Region. Any scan Region resolves `organizations` to the endpoint of the scan's partition.
- **Partition-global**: A service with one endpoint per partition rather than one per Region. `organizations` resolves `us-east-1` and `eu-west-1` to `organizations.us-east-1.amazonaws.com`, `us-gov-west-1` and `us-gov-east-1` to `organizations.us-gov-west-1.amazonaws.com`, and `cn-*` to `organizations.cn-northwest-1.amazonaws.com.cn` (botocore 1.43.105). Pinning `us-east-1` is correct only in the `aws` partition.
- **Provider table**: The `NOT_CONFIGURED_ERRORS` table the provider owns for Organizations operations, of the same `NotConfiguredTable` type and under the same evidence rule as a service base's table.
- **Classification precedence**: `is_not_configured(error)` consults the check's service table first, then the provider table, both keyed by `Operation` then `Code`. A pair declared in either is FAIL; a pair declared in neither is ERROR.
- **Consumer check**: One of the fifteen check modules that read the organization account list on the !54 branch: `sra_inspector_07`, `sra_macie_07`, `sra_organizations_12`, `sra_securityhub_08`, `sra_securityhub_17`, `sra_securitylake_01`, `sra_securitylake_06` through `_13`, `sra_securityincidentresponse_04`. One call site each.
- **The primer**: `SecurityLakeCheck._prime_region_log_sources(region)`, which seeds one `list_log_sources:<account>:<region>` cache slot per organization account from a single regional `ListLogSources` call. The one base method on the branch that reaches into the `organizations` namespace by key.
- **Sweep**: One complete paginated `ListAccounts` read. The one-sweep property is that a scan issues exactly one, whichever service asks first, across every Region and service.
- **Row shape**: Which rows a check emits — how many, with which `Region` and `ResourceId` — as opposed to what those rows say. A refactor that changes row shape cannot be A/B-reviewed.
- **Order-only difference**: Two cells with the same set of account IDs in a different order. `sra_inspector_07`, `sra_securityhub_08` and `sra_macie_07` build cells from a `set`, so this already varies between two runs of `main`.
- **Verdict-stable**: For every row joined on (account, account type, Region, check ID, ResourceId), `Status`, `ActualValue` and `Remediation` are identical between two trees, up to the admitted differences.
- **Reference trees**: `main` at c55893a and the !54 branch at 986bced. Phase 1 is compared against both; Phase 2 against the merged Phase 1.
- **Phase 1 / Phase 2**: The two MRs. Phase 1 replaces !54 and is verdict-stable. Phase 2 moves the rest of the surface and may move verdicts, each with evidence.

## Non-Goals

1. **Reopening placement.** Mixin under `services/organizations/`, method on `ScanContext`, method on `SecurityCheck`, free function — the four were compared in the review (§3) and the owner chose a provider in `core/` composed onto `ScanContext`. The design implements that; it does not re-score it.
2. **Any verdict change in Phase 1 beyond the Inspector first-page effect.** Including the one that looks tempting: declaring `AWSOrganizationsNotInUseException` from `ListAccounts` semantic. No service declares it today, so it is ERROR on both reference trees, and it stays ERROR until Phase 2 produces A/B evidence of the rows it would move.
3. **Region-cell relabelling.** `securityincidentresponse`'s `regions[0]` labelling and `sra_firewallmanager_01`'s literal stay as the steering records them; relabelling moves genuine PASS and FAIL rows and is undiffable against a verdict change.
4. **Set-ordering fixes** in `sra_inspector_07`, `sra_securityhub_08` and `sra_macie_07`. A `sorted()` at each site is correct and cheap and rewrites `ActualValue` cells a consumer may be diffing. Separate MR.
5. **Pagination for `ShieldClient.list_protections`** or any other first-page-only client method. Changes which resources fan out; same deferral as `structure.md` records.
6. **Hoisting the per-scan `accounts()` call above the Region loop** in the twelve regional consumers. On success it is a cache hit; on failure it costs one re-issue per Region per check. Hoisting collapses per-Region ERROR rows into one `global` row — a row-shape change.
7. **The dead branch `if not org_accounts: org_accounts = [self.account_id]`** followed by `is_active_account(account)` on a `str` in the eight log-source checks (`sra_securitylake_06.py:132–134` et al.). Pre-existing, unreachable (a successful `ListAccounts` from a member account always lists at least that account), and touching it widens the diff of files this feature edits for one line each.
8. **Phase 2 work landing in Phase 1**: retiring `org_client` from any service client, replacing `SecurityHubCheck.get_organization()` or `IAMCheck.get_organization()`, migrating `ScanContext.get_account_info` / `get_management_account_id` / `get_enabled_regions` off `raise`, unifying the `ListDelegatedAdministrators` classifications, or widening the AST guard beyond `ListAccounts`. Each is named in Requirement 13 so it is not lost; none is a Phase 1 gate. The *Region* those bindings use is not on this list: `get_enabled_regions`' `ec2` binding and `SecurityHubCheck.get_organization()`'s Organizations binding derive from the scan Region in Phase 1 (Requirement 2 criterion 5); only the `raise` semantics and the provider surface wait.
9. **`sra-verify-mcp`.** The server constructs `SRAVerify` and calls `run_checks`; neither signature changes. Its known breakage (`SRAVerify(debug=False)`, `requires-python >= 3.10`) is a separate change in the other repository.
10. **IAM action-name normalisation** in the generator (`GetWebAclForResource` versus `GetWebACLForResource`). Deliberately unnormalised; the generator's own comment explains why, and this feature keeps "the generated policy is unchanged" meaningful by changing only what it must.

## Requirements

### Requirement 1: One Organizations provider, composed onto the scan context

**User Story:** As a check author, I want one place to ask for organization data, so that every service reads the same answer from the same call and no service carries its own copy.

#### Acceptance Criteria

1. THE Organizations_Provider SHALL be a class under `core/` (for example `core/organization.py`, `core/organizations.py` or a `core/providers/` sibling package; the design chooses), constructed by `ScanContext.__init__` and exposed as the read-only property `Scan_Context.organization` with no setter, so that it has exactly the lifetime of the scan and is dropped with `del ctx` in `run_checks`'s `finally`.
2. THE Organizations_Provider SHALL expose, in Phase 1, exactly one data accessor, `accounts()`, taking no arguments and returning `{"Accounts": [...]}` with every page of `organizations:ListAccounts` merged on success, or the error result unchanged on failure. It takes no Region because the answer is organization-wide; the three per-Region cache slots on `main` were a defect, not a feature.
3. THE Organizations_Provider SHALL cache a successful `accounts()` result on the Scan_Context's response cache under the `organizations` namespace through the existing `_has` / `_get` / `_set` primitives, so that the whole scan issues one sweep whichever service asks first, across every Region and every service, in sequential execution (which is how `run_checks` runs; see criterion 10). The cache key is a design decision; the namespace is not, because it is the one `OrganizationsCheck.NAMESPACE` already names and the one the primer's foreign read has to disappear from.
4. IF the Organizations_Client returns an error result, THEN THE Organizations_Provider SHALL leave the cache slot unwritten and return the error result unchanged, so that the next caller re-issues the call. It SHALL NOT return `{}`, `[]`, `None`, or any success-shaped value for a failure, because an accessor that swallowed the error would hand the check exactly the ambiguous empty value the client-error contract removed.
5. THE Organizations_Provider SHALL have no no-client path, and its docstring SHALL say why: `ScanContext.get_client` always constructs (`scan_context.py:292–345`) and the Organizations_Client binds the result in `__init__`, so the `no_client_result(service="Organizations", region="global")` branch that `OrganizationsCheck.get_accounts` carried on `main` was dead code and is not reproduced.
6. THE Organizations_Provider SHALL issue no AWS call at construction. Acquiring its Organizations_Client — at construction or on first use; the design chooses — goes through `ctx.get_client`, which reads bundled endpoint data and does not touch the network, so `--list-checks`, every Contract_Test that builds a `ScanContext` over a refusing session, and the stdout-contract harness stay credential-free.
7. THE Organizations_Provider SHALL return raw responses and filter for nobody: every Consumer_Check keeps its own `is_active_account` filtering (`core/accounts.py`) and its own management / audit / delegated-administrator exclusions, because those differ per check and moving them would change what a row says. WHERE the design adds a convenience such as `active_account_ids()`, it SHALL be a pure function over a success dict that is never handed an error result, not a second accessor that could erase one; whether to add it, and why, is recorded in the design.
8. THE Organizations_Provider SHALL log at `debug` only, through the `sraverify` logger, with one record on a fetch and one on a cache hit as the mixin does today, and SHALL emit no `aws_call_failed` record of its own — that record stays the Organizations_Client's, one per failed call.
9. THE Organizations_Provider SHALL hold no reference to any check and SHALL be unreachable from any `Finding`, so that `test_context_isolation_property.py` — no `ScanContext` reachable from the returned findings after `run_checks` — continues to hold without amendment.
10. THE Organizations_Provider SHALL be thread-safe to the standard of the existing accessors: cache reads and writes go through the locked primitives, and no second lock is introduced. The cache is double-checked, not single-flight, so the one-sweep guarantee of criterion 3 is scoped to sequential execution: two concurrent first callers may each sweep. Per-key in-flight coordination is a Phase 2 obligation (Requirement 13 criterion 7).

### Requirement 2: The Organizations client is relocated and derives its partition from the scan

**User Story:** As an operator running in GovCloud or China, I want the Organizations call to reach my partition's endpoint, so that the fourteen checks reading organization data work there instead of failing against a commercial endpoint with my partition's credentials.

#### Acceptance Criteria

1. THE Organizations_Client SHALL be the existing `OrganizationsClient` relocated beside the provider in `core/`, inheriting `AWSClient`, keeping all seven methods — `describe_organization`, `list_roots`, `list_organizational_units_for_parent`, `list_policies`, `list_accounts`, `describe_effective_policy`, `list_accounts_for_parent` — with the byte-identical handler `except AWS_EXCEPTIONS as e: return self.aws_error(e)`, every paginator loop wholly inside its `try` (a failure on page three has to arrive as an error result, because a short list is indistinguishable from a smaller organization), and boto3 client acquisition in `__init__` only.
2. THE Organizations_Client SHALL derive its Region from the scan rather than from the literal `us-east-1`: the first explicit scan Region when `ctx.regions` is non-empty, otherwise the session's configured Region (`session.region_name`, which already folds in `AWS_DEFAULT_REGION` and the profile's `region =`; boto3 does not read `AWS_REGION`, and the rule deliberately does not either, so the guard and the clients built from the session cannot disagree). WHEN neither supplies a usable Region string, the scan SHALL be refused with `PartitionUndeterminedError` rather than handed to botocore's commercial `aws-global` default. A non-empty `--regions` whose first value is not a usable Region string (blank, padded, or not a `str`) SHALL raise the same error and SHALL NOT fall through to the session Region: explicit input wins, and explicit input that is wrong is a usage error. The rule SHALL live in one pure function that `SRAVerify`, `get_session` and `ScanContext` all apply. It SHALL issue no AWS call to choose the Region — in particular it SHALL NOT call `ctx.get_enabled_regions()`, which issues `ec2:DescribeRegions` — because a Region chosen by an API call would make client construction network-dependent, which criterion 1's constructor-only rule and `AWSClient.__init__`'s contract both forbid.
3. THE Organizations_Client SHALL pass the derived Region to both `AWSClient.__init__` and `ctx.get_client("organizations", region=...)`, so that the `aws_call_failed region=` record names a Region in the scanned partition rather than `us-east-1`, and so that every path funnelling through this constructor shares one cached boto3 instance under one `(service, region)` key — the "one shared instance" property the pin was bought for is preserved as long as every caller derives the Region the same way, which one constructor guarantees.
4. THE Contract_Tests SHALL assert the derivation offline: a `ScanContext` with `regions=["us-gov-west-1"]` constructs its Organizations_Client with `region_name="us-gov-west-1"`; one with `regions=["eu-west-1"]` with `"eu-west-1"`; one with no explicit Regions over a session configured for `us-gov-west-1` with that Region; and one with no explicit Regions and no session Region SHALL raise `PartitionUndeterminedError` at `ScanContext` construction, with no client built. Partition correctness then follows from botocore's endpoint data (`.tmp/review/endpoint_probe.txt`) and is not re-asserted live, because the test organization is commercial (Requirement 12 criterion 5).
5. WHERE `IAM_Client.org_client` (`services/iam/client.py:38`, pinned `us-east-1`) survives Phase 1 — it does; Phase 2 retires it — THE Organizations_Client's derivation rule SHALL be applied to it as well, so that Phase 1 leaves **no** `us-east-1` pin on an Organizations or Organizations-adjacent binding: `SecurityHubCheck.get_organization()`'s Organizations binding now derives its Region through the same rule, and `ScanContext.get_enabled_regions` binds `ec2` to the scan Region. In the `aws` partition this changes no endpoint and no row.
6. THE Organizations_Client's module docstring, `OrganizationsCheck`'s class and module docstrings, and `structure.md`'s global-service example SHALL stop saying "pinned to `us-east-1`" and SHALL say partition-global with the Region derived from the scan.
7. THE Organizations_Client SHALL be the only module in the package that issues `ListAccounts` in Phase 1, held by the AST guard in Requirement 10 criterion 4. The eight service-client `org_client` bindings, `ScanContext.get_management_account_id`'s `get_client("organizations")`, and `SecurityHubCheck.get_organization()`'s raw call remain in Phase 1 for their other operations and are retired in Phase 2 (Requirement 13).
8. WHEN the scan Region cannot be determined, THE CLI SHALL exit 2, create no output file, and issue no AWS call (not the banner's `sts:GetCallerIdentity`, and not `sts:AssumeRole` under `--role`), logging one ERROR record that names `--regions` and `AWS_DEFAULT_REGION` and states that boto3 does not read `AWS_REGION`; it SHALL NOT advise setting `AWS_REGION`, because that alone still exits 2. THE library SHALL raise `PartitionUndeterminedError`, a `SRAVerifyError`, from `SRAVerify.run_checks` before selection and before a `ScanContext` exists, and from `SRAVerify(role_arn=...)` before `AssumeRole`. When both the partition and the filters are bad, the partition error SHALL be the one reported. `--list-checks` and `--list-services` without `--role` SHALL stay region-free and credential-free.
9. EVERY boto3 client binding in `core/`, `scanner.py`, `cli.py` and `utils/` SHALL name its Region with a value derived from the scan, with no Region-less binding and no literal, held by an AST rule whose allowlist is empty; and `ScanContext.get_client(service)` with no Region SHALL bind the scan Region, so Region-less bindings in service code reach the scan's partition too. Shield, WAF for CloudFront, Firewall Manager's admin API and CloudFront remain `us-east-1`-only and address the `aws` partition. Making them partition-aware needs a per-partition control-plane Region map and is out of scope, and every document that claims partition-awareness SHALL say so.

### Requirement 3: Error classification has two tables, and Phase 1 moves no verdict

**User Story:** As a consumer of the report, I want an Organizations failure classified the same way whichever check hit it, and I want this refactor to change no verdict, so that a diff between two scans measures the refactor and nothing else.

#### Acceptance Criteria

1. THE Organizations_Provider SHALL own one `NOT_CONFIGURED_ERRORS` table, the Provider_Table, of type `NotConfiguredTable`, for Organizations operations, under the same rule as every service table: every entry is a `NotConfigured` whose `evidence` is non-blank and cites either the AWS API reference page documenting the code's meaning for that operation or an `aws_call_failed` record observed from a controlled account. `test_discriminator_property.py`'s shape, evidence and placeholder rules SHALL apply to it.
2. THE Discriminator SHALL consult the check's service table first and the Provider_Table second, both keyed by `Operation` then `Code` with the optional message needle; a pair declared in either resolves to FAIL and a pair declared in neither resolves to ERROR. The service table takes precedence where both declare the same pair, so a service that has already classified a pair keeps its classification and its message needle.
3. THE Provider_Table SHALL declare nothing for `ListAccounts` in Phase 1. No service table declares `ListAccounts` today (`.tmp/review/q6.txt`), so `AWSOrganizationsNotInUseException` from it is ERROR on both reference trees, and it SHALL remain ERROR in Phase 1. Declaring it converts "we could not list the accounts" into "there is no organization" for every Consumer_Check at once, and that is a Phase 2 decision requiring A/B evidence of the rows it moves (Requirement 13 criterion 4).
4. THE Provider_Table MAY therefore be `{}` in Phase 1, and the precedence mechanism of criterion 2 SHALL be implemented and tested regardless — with a synthetic entry in the Contract_Tests, not a real one — because Phase 2 populates it and the mechanism is the seam Phase 2 lands on.
5. THE Check_Catalog SHALL be verdict-stable in Phase 1 against both reference trees: for every row joined on (account, account type, Region, check ID, ResourceId), `Status`, `ActualValue` and `Remediation` are identical, with exactly two admitted exceptions. (a) Order-only differences in cells built from a `set` in `sra_inspector_07`, `sra_securityhub_08` and `sra_macie_07`, which already vary between two runs of `main`. (b) Against `main` only, SRA-INSPECTOR-07 rows in an organization of more than 20 accounts, where `main`'s first-page read hid accounts the paginated read sees. The 13-account test organization cannot exercise (b), so in the Phase 1 gate it SHALL contribute zero differences, and the report SHALL say the effect is covered by the pagination unit test alone.
6. THE Check_Catalog SHALL keep every ERROR `ActualValue` from a failed sweep in the shape `ListAccounts failed: <Code>: <Message>`, and every such row's remediation SHALL remain `self._remediation_for(error)`, so that a consumer diffing against !54 sees identical text and `test_every_error_row_names_the_failed_operation_and_code` holds unchanged.
7. `SecurityCheck.is_not_configured` SHALL remain the only classification call site in a check; no check compares a code inline; and the `__init_subclass__` rule that a *check* may not declare `NOT_CONFIGURED_ERRORS` (`_SERVICE_ONLY_NAMES`) is unchanged. The provider is not a check and is not subject to that rule.

### Requirement 4: Services import core; core never imports services

**User Story:** As a maintainer, I want the dependency edge to run one way, so that the provider cannot create the import cycle that kept the mixin out of `core/`, and so that nothing under `core/` can register a check as a side effect of being imported.

#### Acceptance Criteria

1. THE Organizations_Provider and Organizations_Client SHALL import only from `core/` and third-party packages, and no module under `core/` SHALL statically import `sraverify.services` or any of its submodules. THE Contract_Tests SHALL assert this by an AST walk over every module under `core/`, because the cycle is real: importing any `sraverify.services` submodule runs `services/__init__.py`, which imports every check, which imports `core.check` — confirmed empirically as "importing just `services.organizations.client` registers all 182 checks" (`.tmp/review/q1-cycle.txt`).
2. `core/discovery.py`'s run-time edge through `importlib` SHALL remain the only permitted `core → services` dependency, and it is unchanged.
3. `services/organizations/base.py`, and every other module needing the client, SHALL import the Organizations_Client from its `core/` location. Whether `services/organizations/client.py` survives as a one-line re-export or is deleted is a design decision; either way the Contract_Tests enumerate the class exactly once (Requirement 10 criterion 2).
4. `services/organizations/accounts.py` SHALL be deleted, and no use of `OrganizationAccountsMixin`, `ORGANIZATION_ACCOUNTS_NAMESPACE` or `ORGANIZATION_ACCOUNTS_KEY` SHALL remain in package code (the package and its tests), held by an AST walk over identifiers, imports and definitions. Docstrings, comments and Markdown, the Steering_Docs included, MAY name them as history, so a later phase can explain the migration.
5. The accessor surface SHALL be shaped by what checks consume — `delegated_administrators(service_principal)` cached per principal, `describe()`, `management_account_id()`, `roots()`, `ous_for_parent(parent_id)`, `policies(policy_type)`, `policies_for_target(target_id, policy_type)`, `describe_policy(policy_id)`, `effective_policy(policy_type, account_id)`, `accounts_for_parent(parent_id)` — with the exact names a design decision and the coverage not.
2. EVERY `org_client` binding in a service client SHALL be retired; `SecurityHubCheck.get_organization()` — the raw boto3 call with inline error-result construction and its own `us-east-1` pin — and `IAMCheck.get_organization()` SHALL read through the provider; `OrganizationsCheck`'s six remaining accessors SHALL either delegate to the provider or be replaced by it; and the AST guard SHALL widen to "no module outside the provider's client issues any `organizations` operation", by either spelling.
3. THE Scan_Context's three raising accessors — `get_account_info`, `get_management_account_id`, `get_enabled_regions` — SHALL move to the same model: an error result returned and never cached, no `raise Exception(...)`, no `logger.error` for a failed call. `get_enabled_regions` SHALL derive its `ec2` Region from the session rather than the literal `us-east-1` (`core/scan_context.py:519`), and `SecurityCheck.get_management_accountId`'s one caller (`sra_securityincidentresponse_05`) SHALL consume an error result rather than rely on a raise. Because `_finding` reads `get_account_info()` for every row, the design SHALL decide how a failed `sts:GetCallerIdentity` is reported without a `try` / `except` in any `execute()`.
4. THE Provider_Table SHALL unify the `ListDelegatedAdministrators` classification: today only `IAMCheck` declares `AWSOrganizationsNotInUseException` semantic for it (`iam/base.py:83`), so the same AWS answer is FAIL through an IAM check and ERROR through seven other services' checks. Unifying moves verdicts, and every moved row SHALL be listed by check ID and branch with A/B evidence in the Phase 2 gate before the entry is committed. The same evidence rule governs any `ListAccounts` entry (Requirement 3 criterion 3) and any entry for `DescribeOrganization` beyond what the service tables already declare.
5. PHASE 2 SHALL regenerate the IAM artefacts and expect no new action, because every retired `org_client` call is already granted; a diff other than attribution order is a finding to explain. The `aws_call_failed region=` record for the retired paths changes from the scanned Region to the derived one; the row's `Region` cell does not, and the Phase 2 gate SHALL confirm that.
6. PHASE 2 SHALL NOT relabel any Region cell (Non-Goal 3), SHALL NOT hoist any per-scan call above a Region loop (Non-Goal 6), and SHALL carry forward every deferral `structure.md` records that it does not explicitly close.
7. BEFORE concurrent scanning lands, THE Organizations_Provider SHALL coordinate in-flight first calls per cache key, so that one sweep per scan holds under concurrency and not only sequentially. AND before deciding on any non-retryable failure marker, Phase 2 SHALL measure the denied-`ListAccounts` path at full breadth (every consumer, every Region; on the order of 220 calls in a broad scan). The never-cache-a-failure rule stays until that measurement justifies a constrained exception.
